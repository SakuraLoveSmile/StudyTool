# T4 日志读取异常验收修复（2026-09-18）

## 验收口径

按用户本次 Windows 验收反馈，EACCES 被归类为“缺失文件”且显示零记录属于产品缺陷，维持失败判定，不降低标准。
用户确认候选版 T2b 导航链、遮罩截图、附件、升级保留达标；这些是用户实机反馈，并非本轮重测。
本轮仅修复日志读取异常及相关回归。整体 T4 仍为**实现中**，须让新 Windows 安装包通过 ACL 复测。

## 本轮实现

- 移除读取层 `existsSync` 吞错路径；仅 ENOENT 表示未找到文件。
- stat/open/read 权限拒绝及 I/O 异常通过现有 LOG_QUERY_FAILED 通道返回；提示包含来源与错误码，不暴露系统路径。
- 页面显示红色 alert，失败时不再展示“共 0 条”；已有记录保留并标明是上次成功读取的数据。
- 查询错误独立保存，导出等操作不会清除它；查询成功后清除，恢复权限可手动刷新。
- 未找到文件改为“未找到日志文件（可能尚未生成）”。活动文件暂缺时继续读取轮转历史；扫描预算未覆盖的来源不误报缺失。
- 保留反馈附件部分来源成功、全部不可用时明确失败，以及诊断导出内存兜底和最新记录优先的行为。

- desktop：`npm run build && node --test --test-reporter=spec dist/tests/*.test.js`，101 项全套通过。

- 真实 Worker 覆盖 ENOTDIR 和本机临时目录 chmod 权限拒绝→恢复查询；POSIX 权限用例不能替代 Windows ACL。
