# StudyTool 联网服务 0.1.6

修复章节生成错误丢失具体原因的问题。模型响应成功解析后，原文引用缺失、引用超出资料范围、摘录不在原文中或章节字段不完整，过去都会显示同一句笼统的“模型生成失败或返回的章节资料、原文引用未通过校验”。

- 任务顶部错误与执行日志分别显示安全的校验原因和字段路径，便于区分模型调用失败、返回内容格式错误、章节结构错误与引用错误。
- “校验失败 → 诊断详情”提供固定错误编号、失败字段和错误数量；不记录模型返回值、引用正文、提示词或密钥。
- 保留精确原文引用与资料范围校验，未通过的结果仍不保存；不补造引用或静默丢弃不合法内容，也不增加自动模型调用。
- 历史错误无法补回此前未保存的原因。更新后新执行的任务才会记录详细校验信息。

## 验证

- 95 项相关后端回归通过，包含 23 项新增校验诊断测试；前端构建通过。
- 真实本地网页配合隔离数据库及本机模拟模型，验证引用不匹配、缺失背诵字段的具体提示与诊断详情，刷新后错误仍保留，合法结果正常保存。
- 未调用真实付费模型，未修改生产服务器；已有生产任务的具体失败字段仍需更新后新任务的日志确认。

## 更新

```bash
docker compose --env-file .env pull
docker compose --env-file .env up -d
```

使用 `ghcr.io/sakuralovesmile/studytool:0.1.6` 或本次发布后更新的 `latest`。模型、超时及百度 OCR 配置沿用现有值。按需重新执行失败任务后，在任务顶部与“执行日志 → 校验失败 → 诊断详情”查看原因；重新生成会调用已配置的模型并使用其额度。
