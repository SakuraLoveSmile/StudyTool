# StudyTool 联网服务 0.1.12

修复回忆卡点击“审核并发布”返回 409 的问题。此前网页先审核、再用审核前的卡片版本号发布，审核递增版本后，发布会被自身的乐观锁拦截；卡片可能停留在“已审核、未发布”状态，刷新后还会失去发布入口。

- “审核并发布”改为一次服务端事务：验证当前卡片版本和草稿后，完成审核与发布。保存失败时一起回滚，不留下新的半完成状态。
- 已被旧版审核成功但尚未发布的卡片显示“继续发布”，可直接恢复，无需重新生成或导入。
- 保留真正的过期版本冲突，拒绝其他卡片的引用及旧修订覆盖当前草稿；错误提示展示服务端的具体原因。仅查看已发布内容时，不提供对隐藏新草稿的审核操作。
- 拒绝修改不再接着提交携带旧版本号的冗余请求；拒绝已发布卡的新草稿时，保留原发布状态、正文、暂停或归档状态和复习进度。
- 默认保留已有学习进度，既有审核、发布接口继续兼容，无数据库迁移。

## 更新

```bash
docker compose --env-file .env pull
docker compose --env-file .env up -d
```

版本镜像：`ghcr.io/sakuralovesmile/studytool:0.1.12`；发布验证通过后同步更新 `latest`。更新后刷新网页，新候选点击“审核并发布”；之前卡住的已审核卡点击“继续发布”。

## 验证

旧版真实浏览器复现了“审核 200 → 发布 409”，并确认数据库留下 approved 修订而没有发布版本。修复后真实浏览器验证新候选发布、旧 approved 卡在手机视口继续发布、真实版本冲突的具体提示、刷新新草稿后发布，以及拒绝草稿后旧正文保留。

后端专项及相关学习、联网账号隔离回归共 46 项通过，包括过期版本、跨卡及旧修订拒绝，发布失败后的整笔回滚，重复发布不再写入，默认保留进度与显式重置，以及已发布、暂停和归档三态的草稿拒绝。前端构建和独立只读审查通过。

验证使用隔离临时数据库与本地 API，未调用真实付费模型或 OCR，未操作生产服务器。
