# StudyTool 联网服务 0.1.8

修复“批量生成回忆卡”提交即返回 HTTP 422 的问题：网页过去只提交章节与提示词，后端却要求知识点单元，且页面没有显示后端的中文错误原因。

- 弹窗增加 1–20 个已有知识点的明确选择，提交 `knowledge_point_ids`，未选择、加载中或提交成功后禁止重复提交。生成后仍作为待审核候选，不自动发布。
- 显示后端中文错误，例如来源不足、章节归属不符或原文已变化，便于处理具体问题。
- 修复知识点结构化来源字段未读取的问题，并读取已正式接受或合并的提取引用。验证资料归属、原文内容哈希、精确摘录和来源状态后，按真实引用建立生成快照，避免大教材被误当成整本输入。
- 保留单次 20 个知识点、单知识点 10 个原文切片与 12000 字符上限，不截取前几片来掩盖来源不明。手工 JSON 切片引用继续支持；教材名、页码或裸字符串说明不能当作可靠切片编号，缺少准确引用时需先核对或重新提取。
- 不改数据库结构或已有回忆卡，不增加自动模型调用。

## 验证

- 46 项相关后端回归及前端构建通过。
- 本地真实网页使用隔离数据库与本机模拟模型，验证未选知识点不能提交、真实 422 中文错误展示、有效知识点成功入队并生成待审核卡，刷新后仍存在。
- 390×844 手机视口验证弹窗选择与提交，提交成功后按钮禁用；15 个切片的模拟教材只采用明确引用的 1 个切片。
- 未调用真实付费模型或 OCR，未修改生产服务器。真实服务商生成仍需更新后按需验证。

## 更新

```bash
docker compose --env-file .env pull
docker compose --env-file .env up -d
```

镜像为 `ghcr.io/sakuralovesmile/studytool:0.1.8`，发布验证后同步更新 `latest`。刷新网页，打开“回忆卡库 → 批量生成回忆卡”，选择目标章节与知识点后提交；手动生成会使用已配置模型的额度。若没有知识点，请先在“考点分析”中提取并审核。
