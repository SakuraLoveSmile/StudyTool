# StudyTool 联网服务 0.1.11

修复主动回忆卡生成因模型改写引用原文而出现部分失败的问题。此前模型需要自行抄写引文和来源哈希，内容虽返回成功，引用不匹配教材切片时仍会被拒绝。

- 改为让模型选择输入中已有的原文片段编号，由服务端从当前知识点的不可变快照还原准确引文、教材位置及哈希，减少抄写偏差。
- 继续拒绝无效、过期、超出当前输入范围、纯空白、相互矛盾或重复的引用；兼容既有快照与旧引用格式，不通过模糊匹配修补引文。
- 网页任务详情直接展示失败知识点及原因，旧任务已经保存的失败明细也可查看。执行日志新增逐知识点引用校验、保存结果及失败阶段，便于区分来源变化、模型调用、引用校验与保存问题。
- 原部分完成任务可直接重试，复用已成功知识点，只补做失败项，不重复生成已成功的卡片。

## 更新

```bash
docker compose --env-file .env pull
docker compose --env-file .env up -d
```

版本镜像：`ghcr.io/sakuralovesmile/studytool:0.1.11`；发布验证通过后同步更新 `latest`。更新后刷新网页，在原任务查看失败原因并点击“重试任务”。已有成功卡片会保留，无需重新导入或 OCR。

## 验证边界

相关后端回归共 143 项通过，前端构建及独立只读审查通过。覆盖 19 个知识点首次 13 成功、6 个引文失败后，仅重试失败的 6 项且不重复入卡。

真实浏览器验证了桌面与 390 像素手机视口下的失败列表、日志诊断与重试流程：两个知识点首次一成一败，重试后共两张待审核卡，成功知识点模型仅调用一次，失败知识点调用两次；保存引文及哈希与原文一致。

上述验证使用隔离数据库和模拟模型。未调用真实付费模型或 OCR，未操作生产服务器。本次修改降低引用格式错误，不能保证模型回答的语义质量或外部服务速度。
