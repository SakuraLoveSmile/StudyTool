# StudyTool 联网服务 0.1.3

改善 AI 任务的超时诊断：任务错误与执行日志会指出实际失败阶段，并保留模型、单次网络等待上限、每次尝试耗时及重试次数。

- 区分等待本地调用名额、连接池、TCP 连接、TLS 握手、发送请求、等待响应头、读取响应正文、HTTP 状态与结果解析；连接复用时不会虚构一次新建连接。
- 任务日志新增可展开的“诊断详情”，包括调用 ID、已收到的 HTTP 状态及上游请求 ID。刷新后仍可查询，不记录提示词、教材正文、响应正文或密钥。
- 尚未收到响应头时，会明确提示“暂不能区分服务商处理与上游网络等待”，避免把等待直接归因于 OCR、模型算力或本机网络。
- 本次不调整模型、超时配置或重试策略。历史日志无法补回未记录的信息，更新后重新执行任务才会生成新诊断。

## 更新

使用 `ghcr.io/sakuralovesmile/studytool:0.1.3` 或本次发布后更新的 `latest`：

```bash
docker compose --env-file .env pull
docker compose --env-file .env up -d
```

刷新网页，重新执行失败的章节生成任务，在“任务 → 执行日志 → 诊断详情”查看具体阶段。更新不会自动重试任务或调用付费模型。

## 验证

103 项隔离后端检查、网页生产构建与桌面 TypeScript 构建通过。真实浏览器配合本地 HTTP 模型夹具验证响应头超时、正文读取超时、成功重试和刷新后日志保留；未调用真实付费服务或更改生产数据。
