# 联网知识库使用说明

知识库入口为 `/library`。Windows 和安卓使用同一个 HTTPS 网址、同一个账号，即可访问该账号的资料、章节解读和问答历史。除了网页/PWA，也提供独立的 [安卓 APK](../clients/android/README.md) 与 [Windows 联网安装包](../clients/windows/README.md)，首次填写服务地址。原 Windows Electron 本地版继续独立使用，本地数据库不会自动上传或迁移。

## 从教材到学习资料

1. 在“资料与真题”导入教材和真题，等待解析完成。教材选择“教材”；试卷与答案合卷可选择“真题及答案”。扫描 PDF 需先配置 OCR，解析完成不代表真题已人工确认。
2. 在“知识库”选择教材和章节。DOCX 使用内容块/段落定位，不提供推算页码。新版解析保留章、节上下文，递归读取内容控件和文本框；图片、公式及识别错字仍须对照原文件核实。旧资料需要重新解析后才会获得新版结构。
3. 可选其他管理学教材作为关联依据，选择真题作为已考核对范围。不提供管理学教材时，跨学科内容只标为关联建议。
4. 点击“生成章节资料”。结果包含章节总结、概念解释、可展开思维导图、关键词与背诵段落、管理学关联。每次结果保存在服务端，可以切换历史版本。生成会使用已配置模型并可能消耗服务额度。
5. 点击引用查看精确原文摘录，也可以打开原文件校对。生成期间来源变化会拒绝保存；历史来源发生变化或删除后，界面提示过期并停用引用。

章节生成会读取完整已解析章节，真实确认真题作为证据一起参与重点分析；正文与真题证据合计超过 80000 字符时明确拒绝，不会静默丢掉章末内容或真题。管理学补充材料采用相关片段。生成内容仍需核对，引用校验不等于结论一定正确。

## 真题重点与管理学关联

“真题已考”仅来自当前真题文档中的人工确认、非模拟题目及既有考点关联，题干必须能在当前来源切片中核对。章节中能找到对应考点名称时，概念和导图显示重点标记，同时列出实际年份、题干和位置。人工补题、校对后重新确认及批量确认均遵守现有正式题库语义。

没有关联显示“暂无已确认真题关联”，不等于历史从未考过。模型输出的年份、题号、考频不作为已考证据。管理学关联分为“关联建议”和“有教材依据”，二者都不会直接变成已考标记。

## 问答与追问

选择资料后提问，可以限定当前教材的一章，也可以在多份资料的全部章节检索。问答先限定资料范围再进行词法检索，不另行调用收费 Embedding。回答提供原文引用；没有足够匹配时明确提示资料不足。

继续追问沿用相同的资料和章节范围。历史只用于理解语境，不作为教材事实来源。回答保存在账号的数据库中，另一设备登录相同账号可回看。资料过期或刷新无法核实时，停用引用和追问；后端会逐条核验实际采用的历史，来源已变化时返回409且不调用模型，需要按最新资料重新提问。

## 上线配置与验证边界

沿用 [部署与备份说明](../deploy/README.md) 配置 HTTPS、账号隔离、LLM、OCR 与现有导入所需的 Embedding 服务；密钥只放服务端环境，不填写在网页中。网页设置用于查看服务状态。新增接口继承现有登录、CSRF 与租户边界。部署前备份数据；`library_v1` 增量建表前会按现有机制创建数据库备份，不改写教材、题目或已有学习进度。

安卓和 Windows 网页共用同一套服务端配置。“模型与系统设置”展示 LLM、Embedding 与当前选定 OCR 的配置状态、接口地址及模型名称；不在浏览器保存密钥。修改服务端配置后需要重启服务，再点击“刷新状态”。“已配置”只表示所需配置已填写；刷新状态不会调用收费服务，也不代表真实连通性已通过。Windows Electron 本地版仍使用系统安全存储与桌面设置表单，与联网网页的服务端配置独立。

### 通用 OCR 与百度 OCR

通用 OCR 支持 OpenAI 兼容的视觉 `chat/completions` 接口，需要模型本身支持图片输入与文字识别。独立地址与密钥必须一起配置，不会把问答模型的密钥发送到另一个 OCR 服务。下例放在服务端环境文件（本地为 `backend/.env`，部署为 `deploy/.env`），密钥使用自己的硅基流动 API Key：

```dotenv
OCR_MODE=vision_llm
OCR_BASE_URL=https://api.siliconflow.cn/v1
OCR_API_KEY=<硅基流动 API Key>
OCR_VISION_MODEL=PaddlePaddle/PaddleOCR-VL-1.5
OCR_TIMEOUT=120
```

该模型使用官方 `OCR:` 任务提示词，逐页发送真实图片；它提供文字识别，不承诺多栏顺序、表格结构和公式版面的完整还原。输出被模型截断时明确报错，不把半页识别结果作为完整原文保存。其他协议的专用 OCR HTTP 服务需要单独适配，不能只填地址直接通用。

切回百度时，将 `OCR_MODE` 改为 `paddleocr_api`，同时填写 `BAIDU_OCR_API_URL` 和 `BAIDU_OCR_TOKEN`，重启服务。只使用选定服务，不会因为队列满而自动切换到其他计费服务。兼容旧配置：`OCR_BASE_URL` 和 `OCR_API_KEY` 均为空时，通用 OCR 复用问答服务地址与密钥；仍须将 `OCR_VISION_MODEL` 设置为实际支持视觉的模型。

网页“模型与系统设置”中，LLM、Embedding 和 OCR 各有“测试连通性”按钮，使用服务端已保存的配置，显示测试中、通过或失败原因及耗时。测试期间禁止重复点击；未配置的服务无法测试。“刷新状态”会清除本页测试结果并重新读取配置。测试会实际调用供应商，可能产生少量费用；OCR 只发送内置合成图片，最多一次提交，不自动重试。普通页面加载与刷新状态不会调用模型。测试结果只保留在本页，配置完成状态与本次测试结果分别展示。

接口为 `POST /api/desktop/test-connection`，请求体 `{"service_type":"ocr"}`（LLM/Embedding 分别使用 `llm`/`embedding`），网页不携带密钥或自定义供应商配置；公网模式沿用现有会话与 CSRF 请求机制。

添加桌面入口需要安全网址。安装入口不保存离线资料；service worker 所有同源请求均走网络，使用 `no-store`，不使用 Cache Storage，不缓存账号资料或旧资源包。离线时不承诺阅读、问答或复习功能。

本次本地验收数据位于 git 忽略的 `artifacts/connected-library/`，与原有资料库隔离；原始教材和真题未修改。真实教材已验证 21 个正文章节；扫描真题保留为待 OCR，未伪造解析结果或确认题目。本地模型替身的结果显式标为“隔离界面验证样本”，仅证明界面/API/协议和持久化链路，不代表真实模型分析质量。公网部署、付费服务调用、全部真题 OCR 和安卓/Windows 真机安装仍需分别验证。
